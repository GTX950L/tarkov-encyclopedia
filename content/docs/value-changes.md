# 游戏数值变更台账

<a id="top"></a>

> “同一个数字，在不同版本里可能差一倍——台账就是让你知道它变过。”
> —— 本页只回答一件事：**哪个值，在哪一版上，从多少变成了多少。**

---

## 📸 基本信息

| 项目 | 信息 |
|------|------|
| **类型** | 游戏侧数值与规则变更的**版本轨迹台账** |
| **收录范围** | 只收**站内正文已经写明、且能指出版本分界**的变更 |
| **粒度** | 单条数值 / 单项规则开关（不是“这一版更新了什么功能”，那是[重大版本更新史](version-history.md)的事） |
| **当前基线** | 1.1.5.1（2026-09-15）· 第一赛季 KORD BREACH |
| **登记口径** | 每条必须带**版本分界 + 来源层级 + 正文出处**，缺任一项不入表 |
| **默认模式** | 持久 PvP（见[数据口径与引用说明](citation.md) 第二节） |

## 🧭 本页与另外四页的分工（先看这一节，防止第五处重叠）

站内已经有多处记录“变化”，本页**不与它们重复**——各自管一个层级：

| 页面 | 管什么 | 层级 |
|------|--------|------|
| [重大版本更新史](version-history.md) | 哪些更新**改变了玩法结构** | 版本级（2016–2026 全史） |
| [更新日志](../CHANGELOG.md) | **本站**收录与修正了哪些条目 | 站点级（每批） |
| [待收录清单](roadmap.md) 的「📈 版本敏感内容」 | 哪些条目**下次要复核** | 待办级 |
| [数据口径与引用说明](citation.md) | 引用时**能说什么、要加什么限定语** | 口径级 |
| **本页** | **游戏数值本身**在版本之间的取值变化 | **数值级** |

> **为什么值得单开一页**：另外四页回答的是“站点怎么维护”“话该怎么说”，**没有一页回答“这个数字以前是多少”**。而 A 类未决项（如出血速率）恰恰说明——**同一个量在不同版本里确实取不同的值**，散落在各页的正文里，读者查不到全貌。

## 📊 数值类：同一量在不同版本的取值

**表里的“旧值”一栏若写“—”，表示该量在站内没有留下可比对的旧口径**（不是没变，是站内无据可查）——**这类空缺不要用推测填**，它本身就是待补的诚实标记。

| 数值 | 版本分界 | 变化 | 适用模式 | 来源层级 |
|------|----------|------|----------|----------|
| **出血速率**（轻度 / 重度） | 官方 Wiki **现行版** vs 其历史版本与中文资料 | 历史口径 **0.8 / 0.9 HP** → 现行 **1.36 HP / 6 秒**、**1.53 HP / 4 秒** | 全模式 | 一级（现行）；两口径并存，见 [A11](citation.md) |
| **商人售价基准** | **1.1.0.0**（2026-08） | — → **整体上调约 25%** | 持久 PvP | 一级 |
| **手术包使用时长**（CMS / Surv12） | 中文 Wiki 物品表 vs 社区实测 | 中文 Wiki **16 / 20 秒** vs 社区实测 **5–7 秒**（差约三倍，非版本先后，属口径分歧） | 全模式 | 两说并存，见 [A10](citation.md) |
| **耳机音量放大曲线** | **0.16.5.0** | 戴与不戴、款与款之间的音量差**被拉平**（曲线数值官方从未公布） | 全模式 | 一级（变更本身）；数值见 [B4](citation.md) |
| **PMC 业力** | **0.15.0.0** | — → **引入**（触发项官方声明会持续增加） | 持久 PvP | 一级，见 [B2](citation.md) |

## 规则类：可用性、开关与结构的变化

规则类没有“旧值/新值”这种可比对的数，但同样有**明确的版本分界**——引用时要能说清“这是哪一版之后才成立”。

| 规则 | 版本分界 | 变化 | 适用模式 | 来源层级 |
|------|----------|------|----------|----------|
| **保险服务可用性** | **1.1.0.0**（第一赛季起） | 所有档案可用 → **赛季 PvP 禁用** | 赛季 PvP | 一级 |
| **跳蚤市场开市条件** | **1.1.0.0** | 与商人**忠诚度挂钩**（赛季还会进一步延后） | 持久 PvP | 一级 |
| **任务解锁结构** | **1.1.0.0** | 线性前置链 → **按忠诚等级分组**，组内完成到一定数量解锁下一档 | 全模式 | 一级 |
| **Kappa 安全箱前置** | **1.1.0.0** | “集齐数百个任务”式清单 → **4 项可核对硬条件** | 全模式 | ⚠️ 存疑，见 [A1](citation.md) |
| **AI 侦测系统** | **0.16.1.3** | “知道你在哪”式全知 → **距离 / 角度 / 姿势 / 天气 / 植被分项判定** | 全模式 | 一级 |
| **普通 Scav 的压制射击** | **0.16.1.3** | 保留 → **已取消** | 全模式 | 一级 |
| **Scav 侵略性** | **0.16** | — → **提高** | 全模式 | 一级 |
| **AI PMC 的四档态度与环境变量** | **0.15.0.0** | — → **引入**（官方声明会在 PvP 与 PvE 中持续平衡） | PvP + PvE | 一级，见 [B3](citation.md) |
| **护甲与命中判定区** | **0.14.0.0** | — → **重做** | 全模式 | 一级 |

## 🧭 维护规则（怎么往里加）

1. **只登记有版本分界的变更**。不知道是哪一版变的，就**不要猜**——按站规记进[数据口径与引用说明](citation.md) 第三节，而不是在这里编一个版本号。
2. **必须指回正文出处**。台账本身不是事实源，[条目](../entries/index.md)才是；本页的作用是**索引**，值以正文为准。
3. **两个口径并存时，两栏都写**。不要为了表好看而只留一个——那不是台账，是结论。**删掉任一栏都算漏改**（A10、A11 已由 `check_promises.py` 登记断言）。
4. **没有可比对旧值的，旧值写“—”，不写估算**。空缺是诚实标记，估算会污染整个台账。
5. **新赛季开始、官方补丁说明发布后回来核一遍**（与[数据口径与引用说明](citation.md) 第七节的复核触发条件同步）。
