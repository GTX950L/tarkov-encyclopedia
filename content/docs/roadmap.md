**grep 只能发现「站内没写的词」，发现不了「站内没想到要写的东西」**。

| ① | 三个分区过长 | 形态 | 标题栏改成折叠开关（`<button>` + `aria-expanded`），已完成默认折叠，加「全部收起 / 展开」 |

| ④ | 数量不对 | **数据** | 生成器口径错（下详），影响 278 组 / 281 条 |

#### ④ 的根因（本批唯一的数据缺陷）

「找到 N 个 X」与「上交 N 个 X」描述的是**同一批东西**，生成器却把它们**相加**。
玩家实际只需凑 N 个（找到后原样交上去），相加等于算了两遍 —— 数量系统性翻倍。

新口径：可消耗的（交 / 放 / 用）**求和**，「找」（获取）**求和**，两者**取较大者**。
找 3 交 5 → 5；找 3 交 3 → 3；交 2 + 交 3 → 5。

| 任务 | 物品 | 修前 | 修后 |
|------|------|------|------|
| 不良嗜好 | 马宝路 / 云尔斯顿 / 无彩香烟 | 30 | **15** |
| 半导体危机 | CPU 风扇 | 16 | **8** |
| 肥料 | 电线 | 20 | **10** |

> **留档的教训**：目标清单里的**单个目标数量是对的**（每个目标说清自己要几个），
> 错的是**合并那一步**。查这类问题时不要从数据源翻起，先看聚合函数。

#### 形态三处的实现要点（留档）

- **折叠状态必须活在渲染函数之外**：本页每次交互都重建 DOM（`sync()`），状态挂在元素上会被一起清掉；
- **折叠后标题栏不能消失**：「有多少个」是决策信息，跟着列表一起收起就等于没折叠；
- **面板限高 + 标题条 sticky**：清单长起来会顶满整屏、把任务列表挤走；sticky 保证随时能点「收起」；
- **打开时主动滚入视野**：面板渲染在工具栏下方，若读者正停在页面下方，只渲染不滚动会被读成「点了没反应」。

#### 登记未做（按纪律不夹带）

| 项 | 情况 | 处置 |
|----|------|------|
| **货币混在出门清单里** | 卢布 / 欧元 / 美元按 `giveItem` 正常入册，但「带上 1000000 卢布」与「带 5 个电线」不是一件事 | **本批不动** —— 语义上它确实要带；要分开得先定「资金算不算准备项」，属口径问题，不夹带 |
| **「可接」默认展开仍有最多 80 行** | 146 个可接任务按等级升序铺开 | **本批不动** —— 折叠 +「全部收起」已覆盖「太长」的诉求；分批加载是另一轮改造 |
| **准备清单的物品没有图鉴链接** | 清单里只有物品名，点不进物品页 | **本批不动** —— 需先确认站内物品名与图鉴 slug 的映射覆盖率，不能凭猜跳转 |

### 🧭 任务看板第二轮：两个实测缺陷 + 四处体验（第七十二批，v1.105.0）

> **本批的判据（承接第七十一批）**：上一批修的是「读者报上来的」，这一批修的是
> **「拿真实规模量出来的」** —— 只看代码会漏掉这两类：跑一次就知道的问题（grid 撑宽、
> 折叠空建 DOM），和只有到量级才显形的问题（11 张图 184 项时地图块的排序）。

**样本**：44 个进行中任务 / 11 张地图 / 184 条准备项（不是几个任务的手感测试）。

**缺陷一：窄屏下准备清单内部横向滚动**（386px：`scrollWidth 465 / clientWidth 328`）

根因值得留档 —— **`.tk-prep__nm` 的 `min-width: 0` 只管 flex 收缩，
不参与外层 grid 的 min-content 计算**。单列 grid 的隐式列按 min-content 取宽，
于是最长物品名（379px）把整块撑开。修法是 `grid-template-columns: minmax(0, 1fr)`。
**这类「flex 里写过的修法，在 grid 父级不生效」的坑，本批第一次踩到。**

**缺陷二：折叠只隐藏、不省 DOM**（点「全部收起」前后 1941 → 1941，全展开 3505）

折叠只加 `display: none`，行照样建。修后全收起 **205** 个节点。
→ **判据：折叠必须同时省构建**，否则「收起 80 行」这个动作本身没有任何代价收益。

**四处体验**：分区「显示更多」（原先的出口「用搜索框找」走不通 —— 搜索按任务名）、
地图块按缺口排序、跨图同名物品加「另 N 图」标记（**不合并数字**，按图分块是设计意图）、
资金单独成组且不计入缺口。

**登记未做**：准备清单物品链到图鉴 —— **缺数据**（目标只给物品名不给 id，
站内也没有物品名 → 图鉴 id 的映射表），要做需先新建一张 889 个物品名的映射。

### 🧭 生成物防漂移门禁（第七十三批，v1.106.0）

> **本批补的是一条「静默失败」通道。** 站内大量页面是 `gen_*.py` 的产物，且**产物入库** ——
> 于是「改了源数据或生成器、忘了重跑」既不让构建失败，也不让四道门禁变红。
> 站内已有的 `check_drift.py` 查的是**上游端点**漂移，管不到「仓库内产物与源脱节」。

**做法**：**不清点产物清单**（那种清单自己会漂），而是比对**跑前跑后** ——
记录全部跟踪文件的「归一化哈希」→ 按依赖顺序重跑 25 支离线生成器 → 再算一次 → 列出仍不同的。
已接入 `deploy-pages.yml` / `validate-entries.yml` 的校验前置与 `build_all.py`（⑤c）。

**体检结果：当场查出 12 处已存在的脱钩，本批全部修掉**

| 类 | 规模 | 根因 |
|----|------|------|
| **页面基线会回退** | **9 页** | 7 个数值表生成器**各自硬编码** `1.1.5.1`，而站点基线 2026-10-06 已抬到 `1.2.0.0` |
| **人工内容会被整段抹掉** | 2 处 / 18 行 | 内容写在 AUTO-GEN 标记区**内部**，而生成器模板里没有它 |
| 生成日期 | 2 个 js | `generated: today()` —— 每天都会变 |

**修法**：

- 新增 `scripts/_baseline.py` 作**基线唯一来源**（从 `citation.md` 读），7 个生成器改读它。
  顺带暴露一个**漏网页**：9 个同类页面里 8 个已被人工更新到 `1.2.0.0`、**`ammo-table.md` 漏了** ——
  单一来源之后它自动跟上，这就是「一处改、一处不落」。
- 两处人工内容固化进生成器模板（`gen_hideout.py` 的 `STATION_NOTES`、`gen_quests.py` 的字段表）。
- 日期交给门禁**归一化**比对 —— **不追日期**，否则天天假警报，而**假警报比不报更糟**。

**本批新立判据**：

> **「重跑后文件变了」不等于「提交就好」。**
> ① 忘了重跑 → 该提交重跑结果；② 人工内容落在自动区 → **不能提交**（会整段抹掉），
> 要固化进生成器模板。两种情形表现完全相同，**判断权在人**。
> 门禁脚本把这句话直接打印在报错里，手册同步了这一条。

**留档（调试时容易误读的一点）**：`content/quests/index.md` 由 **3 个生成器**协作写入
（`gen_quests` 整页重建 + 另外两个各写一块标记区），存在**顺序收敛** ——
仓库状态必须先与「按序跑一遍的输出」对齐，门禁才稳定。
本地反复出现「第一次报错、第二次通过」，不是门禁不稳定，而是**仓库落后于生成器**。

### 🗺️ 交互地图上线：站规「不做配图」部分解冻（第七十四批，v1.112.0）

> **这一批推翻的是站内自己的规矩，所以按纪律：先记理由，再记做法。**

**推翻了什么**：第十二批留下的「**没有跟着改的两处（有意保留）**」里的**「不做配图」**（原记录见上方该批末尾，已就地加指针）。

**为什么可以推翻**：原始理由是「地图随时可能重做，画一次就腐烂一次」。这条理由针对的是**把地图当图片资产**——图里有字、标注画死在图上，改版就得重画。而上游给的是**矢量 + 分层 + 独立坐标数据**，只要沿用站内既有的「生成器出产物、产物不许手改」范式，改版重跑一次即可。**理由被技术化解，规矩才跟着改**——不是因为想加就加。

**边界（哪一条没改）**：**条目正文仍不列坐标、仍不放图。** 变的是「点位信息有了落点」，不是「正文可以写点位了」。

**留档三条**：

| # | 事 | 处理 |
|---|----|------|
| 1 | 底图是 **CC BY-NC-SA 4.0**（与本站同许可），但**上层版权仍属 Battlestate Games** | 署名与边界写进[引用说明第四节](citation.md)，**不能把 CC 读成「地图版权已获授权」** |
| 2 | 上游附**禁用作弊条款**（in-game radar / ESP / 作弊客户端改图 / pixel-bots，违反即自动撤销许可） | 本站不在范围；但本站是公开仓库，**这句边界需要留痕** |
| 3 | **实验室暂不做** | 上游那张用内联 `fill` 着色、没有可替换的色类表（还带 40 处语义色 `red`）—— **不猜语义色**，留待单独建模 |

**判据（本批新增，可复用）**：

> **推翻一条旧规矩之前，先问它原来的理由是否还成立。**
> 「地图会重做」这条理由**今天依然成立**——它只是从「所以不做」变成了「所以要分离底图与标注」。
> 理由还成立而做法变了，**必须在原处留指针**（本批已在第十二批记录末尾加了一行），
> 否则下一个人读到的就是一条**自相矛盾的站规**。

**记账**：本条同时改动了[引用说明第六节](citation.md)的两行「不覆盖」表、[贡献指南](../CONTRIBUTING.md) 的「不用配图」一条、[地图对照速查](map-guide.md) 与[战利品分布与热点](../entries/loot.md) 的两处「不列坐标」段（均**保留原文理由、只加落点指针**），以及全站篇数口径（11 → 12，五处）。

### 🔗 交互地图接上任务系统（第七十五批，v1.113.0）

> **本批没有动站规。** 上一批（第七十四批）已经把「坐标集中收在交互地图」这条口径立好了，本批是在那个口子里**把内容做实**。

**做法**：新增 `scripts/data/quest_zones.json`（`gen_maps.py` 抓 `tasks` 端点的 `zones`），**与正文数据完全分开存放** —— `gen_quests.py:slim_objective()` 那边**一行没改**，正文侧照旧丢弃坐标。地图读[我的进度](../quests/progress.md)的同一套任务 id 做筛选，不需要桥接表。

**判据（本批新增，可复用）**：

> **「没有破例」的证据不是嘴上说，而是两边数据管线不共享。**
> 如果坐标是从正文那份 `quests.json` 里漏出来的，正文那扇门就等于白关了。
> 本批刻意让坐标走独立管线，**并把这个分工写进[引用说明第四节](citation.md)** ——
> 后来人看到两个地方都有坐标相关字段时，能一眼看懂它们为什么不矛盾。

**如实登记**：上游 504 / 站内 515 的任务差（站内多出的是上游已下线的限时任务，自然无点位）；约 4% 的目标描述因上下游版本对不齐而**不给**，只显示「任务名 + 目标类型」。

### 🗺️ 交互地图补交互：缩放 / 平移 / 单任务点选（第七十六批，v1.114.0）

> **这一批是「把上一批的交互做足」。** 读者上手后直接点出两个缺口：不能缩放、不能单独点选任务。

**做法**：改 SVG 的 `viewBox`（**不引地图库**）—— 点位、任务区域、地名同在一个坐标系里，改它就是三者一起动，不会错位。缩放的标注按 `--tk-k` 反向补偿，保持屏幕大小。

**判据（本批新增，可复用）**：

> **坐标数学靠读代码验证不了，必须跑。**
> `zoomAt()` 里 k 的方向写反（乘而不是除），表现是「往上滚反而缩小」——
> 代码读起来完全通顺，只有**连发 3 次滚轮事件、断言放大倍数等于 1.18³** 才暴露出来。
> **凡是「屏幕坐标 ↔ 数据坐标」的换算，都要留一个可断言的自检。**

**顺带修掉一处「写了但没生效」**：上一批声明「全部模式下已完成的任务区域自动变淡」，实际代码在全量模式把进度快照置空，标记从未打上 —— 只有切到筛选时才看得出差别。本批修正为总是取快照。

**同时补上的入口**（上一批漏做，见 v1.113.1 的修复提交）：工具箱菜单与海关条目页此前都没有通往地图的链接。**新增页面时，「用户怎么找到它」是必查项，`check_entries.py` 拦不住这一类。**

### 🗺️ 对标开源地图项目补全图层（第七十七批，v1.115.0）

> 读者给出两个参考项目（`tiltysola/tarkov-tilty-frontend-opensource` 等），要求据此优化地图。

**先查同源，再谈差距。** 参考项目的交互地图数据（`src/data/interactive_maps.ts`，3.4 MB）与本站用的 maps.json **是同一份**（tarkov.dev 的 interactive maps，作者都是 Shebuka）。所以差距**不在数据源，在图层做得全不全** —— 这一条直接决定了本批方向：**不是换数据，是把同一份数据里没用上的字段用起来**。

**补三个**：撤离点（159，带 `faction`）、上锁（243，**带钥匙物品 id → 直接链物品图鉴**）、危险区（320，带 `outline` 多边形）。

**不补两个**：容器（单图 551 条，**只给位置不给类型**，铺上去只会糊住地图）、出生点（口径已登记为 [B7](citation.md) 未决项）。**画得出来，不等于值得画。**

**判据（本批新增，可复用）**：

> **对标一个开源项目，第一件事是查「两边是不是同一份数据」。**
> **同源** → 差距就是**字段利用率**，方向是「把已有的用起来」，而不是换数据源；
> **不同源** → 才轮到比数据。这一条能省掉一整轮无效调研 —— 本批差一点就去研究它的数据格式了。

### 🗺️ 学 eftarkov.com 的地图界面（第七十八批，v1.116.0）

> 读者给出中文 Wiki 的地图工具（`eftarkov.com/map/<地图id>`），要求学习它的操作界面。

**第三次撞见同一套键。** 它的地图路由用 `55f2d3fd4bdc2d5f408b4567` 这类 id，与本站、与上游**完全同一套**（都源自游戏数据）。此前两次分别是物品 id（上锁 → 物品图鉴）与任务 id（地图 → 我的进度），这次是地图 id。**「两边 id 同源」已是这个生态的常态** —— 每次对接前先验证一次，比事后建映射表便宜得多。

**学到三件事**：右侧任务清单（→ 本站做成地图上方的可折叠清单，按商人分组）、左侧图层清单带条数（→ 图层按钮带条数 + 悬停细分）、右上全屏。

**重点在任务清单**：它解决「想找某个任务、但不知道该往哪看」—— 此前只能在一百多个方框里碰运气。

**没做的**：绘图工具（需本地草稿存储与撤销栈，与本站分工不符）、「我在哪？」（需读客户端日志）、手机查看与组队（需服务端）。

> **看到功能，不等于该抄功能** —— 这三条都不是「做不到」，是**与本站的形态边界冲突**：
> 本站是纯静态、内容在服务端、进度在本机；而它们要么需要服务端，要么需要客户端。

### 🗺️ 学小喵塔科夫的地图界面（第七十九批，v1.117.0）

> 读者给出第三个参考站（`tkf.xiaomeow.cn`，Next.js，13 张图），要求看它的地图。

**一眼看到的差距**：它的撤离点**带名字与类型**（`铁路通道（信号弹）`、`前往立交桥`），而本站只有方块 —— 因为上游的 `extracts[].name` 是 `ex_customs_scav_gasstation` 这种内部 id。**「有数据」与「读者看得懂」是两件事**，这一批补的就是中间那一步。

**改法两层，都不编造**：机械剥离前缀 + 词表（只填能可靠对应的），拿不准的保持英文。海关 28 个里绝大多数已中文化；上游本来给英文名的照抄。**一个错的撤离点名，比一个英文名更糟。**

**没跟的**：深色底图（本站全文浅色、读者偏好浅色）、左右抽屉面板（正文区只有 900px 宽）、右键标点与绘图（需本地草稿存储）。

> **参考站的优点，不都是本站的优点。** 这一条与第七十七、七十八批是同一个判断：

### 🧭 对照 TarkovTracker 与 tarkov.dev 的功能面（第八十批，v1.138.0）

> 目标换成「做成百科与工具一体的塔科夫助手」，对照对象也随之换成**功能最全的两个同类站**：
> [tarkov.dev](https://tarkov.dev)（the-hideout 官方站，数据源就是本站的上游）与
> [TarkovTracker](https://tarkovtracker.org)（Nuxt + Supabase，任务/藏身处/物品进度 + 小队同步）。

**先对齐定位，再比功能。** TarkovTracker 的 README 明确写着「**不需要账号就能用**，进度存在浏览器
localStorage」—— 与本站同一条路；它把账号只用于「跨设备同步、组队、分享、API」。
所以差距不在「有没有进度跟踪」，而在**有没有服务端**。

| 能力 | TarkovTracker | 本站 | 判断 |
|------|---------------|------|------|
| 任务 / 目标勾选、PvP 与 PvE 分账 | 有 | 有（`tarkov_progress_v1`，三套账本） | 同级 |
| 藏身处模块与材料 | 有 | 有（26 模块 + 材料反查） | 同级 |
| 交互地图 + 任务目标点 | 有 | 有（13 张图、522 条区域、撤离/上锁/危险区/转场） | 同级 |
| 进度导出 / 导入 / 分享链接 | 有 | 有（JSON 文件 + 带数据的长链接） | 同级 |
| 跨设备同步、组队实时同步 | 有（需账号） | 无 | **不做**：要有服务端与账号体系，与「纯静态、不收集数据」冲突 |
| 公开 API / API Token | 有 | 无 | **不做**：静态站没有可鉴权的接口 |
| 出生点图层 | 有 | 无（口径登记为 [B7](citation.md) 未决） | 待定：上游给的是稀疏采样点，画上去会被读成「必然刷人点」 |

**学到并已落地的一条**：他们的首屏就是**进度看板**，工具与百科在同一个首屏里并置。
本站 v1.137.0 因此在首页直接放了作战台面板（选图 → 看这张图还有什么任务 → 勾掉），
而不是只留一张「工具箱」卡片链走。

**没跟的一条**：小队同步。本站没有服务器，也没有登录；真要做只能靠「分享链接」这种
异步形式（已有），实时同步必须换架构。
