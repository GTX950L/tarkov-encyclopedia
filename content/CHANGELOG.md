### 1. 表格出现「两个拖动条」（实机发现）

地图篇的表格**上下各一条横向滚动条**。查下来是**嵌套的滚动容器**——三层里有两层在真滚动：

| 层 | `overflow-x: auto` 是谁设的 | 3 列表下是否真溢出 |
|----|------------------------------|--------------------|
| `<table>` 自身 | **本站** `extra.css` | **是**（线上实测 scrollWidth / clientWidth ＝ 764 / 718） |
| `<div class="md-typeset__table">` | **本站** `extra.css`（为 `min-width: 36rem` 配套加的） | **是**（752 / 705） |
| `<div class="md-typeset__scrollwrap">` | Material 主题自带 | 否 |

**两层都溢出 → 各画一条。** 前几轮审查漏掉它，**不是滚动条形态的问题**——`headless`（overlay 滚动条）与**真实 Edge（Windows classic 滚动条）**两种模式都量过，量出来都只有一层。真正卡住复现的是**环境**：本地构建的表格内容宽 **718px**（`table.scrollWidth == clientWidth`，压根不溢出），而**线上**（Web 字体完整加载后的实际字宽）是 **764px**。触发窗口也很窄：只有**正文可用宽落在 `min-width: 36rem`（本例 720px）与内容实际需要宽度（764px）之间**时才出现，对应视口约在 **1220px**（Material 双侧栏断点）附近；常规宽屏下正文更宽，测不到。

**为什么只有一部分表格有**：2 列表未触发 `min-width: 36rem`，两层都不溢出，本来就正常——与「有的表格」这一观察完全对上。

**修法**：把 `table` 自身的 `overflow-x: auto` 改成**显式 `overflow: visible`**（保留 `display: block`），滚动**统一交给 `.md-typeset__table`**。

> 这里**不能只是删掉**。Material 主题自己有一条**同特异性**的
> `.md-typeset table:not([class]) { … overflow: auto }`（表格自身滚动）——
> 只删不写，它立刻接手，表格照样自己滚。必须显式覆盖。
> （主题另有 `html .md-typeset__table table { overflow: hidden }` 想关掉它，但特异性 (0,1,2) 低于 (0,2,1)，被自己那条 `overflow: auto` 打败，形同虚设。）

实测（线上 ground-zero，视口 1220px 附近）：横向滚动条 **6 → 3 条**、**双层表格 3 → 0**；`.md-typeset__table` 的滚动范围 **752 → 781px**，完整覆盖内容所需的 764px。

更隐蔽的一处：本地把内容加宽到 960px 做压力测试时，旧版 `__table` 的滚动范围只有 752px，**有 208px 内容永远滚不到**——修复后变成 977px，完整覆盖。也就是说这个 bug 除了「两条滚动条」，还会**吃掉表格右侧的内容**。

两处 CSS 注释都写清了「为什么必须显式写 `visible`」「主题那条被谁打败」，防止以后有人删掉。

### 2. 导航回顶：补上第二层兜底（P1）

上一版加的 `document$` + `scrollTo` 兜底**不够**。实测（整页加载长条目 → 滚到 2500px → 点左侧导航）：**滚动位置原样保留 2500**，稳定复现；而「切换过一次之后再点」却正常归零——所以只看后一种场景会误判成「已修好」。

**根因**：`history.scrollRestoration` 默认是 `"auto"`，浏览器会在我们复位**之后**把上一页的滚动位置还回来。兜底脚本赢了顺序、输了时序。

**修法（三层）**：

1. `history.scrollRestoration = "manual"`——关掉浏览器的自动滚动恢复（上一层的复位就是被它覆盖的）；
2. 保留原有 `document$` 复位，作为内容就绪后的兜底；
3. **点击导航链接的那一刻就先复位一次**。只靠第 2 层有个体感问题：它要等新页面内容（XHR）就绪才触发，弱网下明显滞后——实测同一操作有时 80ms 归零、有时要等 500–1000ms，读者看到的是「停在半中间顿一下、再跳回顶部」。所以在点下去的瞬间先复位，内容到达后再由第 2 层兜第二次。

**两条放行规则**：带锚点的链接（`#xxx`）不处理——那是读者主动要求跳到某处；**站外**链接不处理——不是站内换页。

> **踩过的坑（值得记）**：站外判断**不能**写成「href 以 `http(s)://` 开头」。Material 构建后，站内导航链接的 href 本身就是**绝对 URL**（`https://…/entries/bosses/`），那一刀会把**所有站内链接都误判成外链**，这一层等于没写——线上表现为「每个页面首次点击仍要等 1.8–3.5 秒才归零，之后变快只是因为 XHR 命中缓存」。正确写法是**比对 `url.origin` 与 `location.origin`**：只有真正跨域才放行。

**实测（线上）**：修复前 100% 失效 → 加第 1 层后仍有滞后（首次点击 1.8–3.5s 才归零）→ 三层齐全且把判断改对后，**5 个页面 × 4 次 = 20/20 在 50ms 内归零**；带 `#categories` 的链接仍停在 1340px，锚点未被打断。

**二、撤回一次误判（值得记下来）**

审计过程中我一度判定「**搜索打不开**」——因为点击搜索按钮后，DOM 里**查不到输入框**（`.md-search__input` 命中 0），勾选 `__search` 复选框也没反应，bundle 里也搜不到相关代码。

**这个结论是错的。** 按下按钮的那个截图显示：**搜索弹窗正常弹出**，输入「撤离」得到 **246 条结果**，右侧还有按标签过滤的面板（机制 107 / 中期 80 / 地图 57…）。

**根因**：Zensical 的新搜索（Disco）把 UI 渲染在 **Shadow DOM** 里，而 `document.querySelector` **不穿透 Shadow DOM**。改用 **playwright 的 locator**（它会自动穿透）之后，`input` 立刻就能定位并输入。

> **这与当初 mermaid 那次是同一个坑**：`attachShadow()` 之后，外部 DOM 查询**永远查不到**渲染结果。**判据：凡是“看不见但有截图为证”的元素，先用能穿透 Shadow DOM 的工具复验，再下结论。**

**三、验证正常、未改动的项**

## 2026-09（v1.30.0）

### 修复：点击左侧导航后，新页面偶尔不停留在顶端

**起因**：读者反馈「点击左侧栏目后到新的页面，并没有直接回到顶端」。

**这个必须实测——而且第一次差点测出错误结论。** 首次测试（从[工厂](entries/factory.md) 滚到 900px 再点导航）结果是 `scrollY = 0`，看起来「没有问题」。**换几个场景重测才发现**：

| 场景 | 结果 |
|------|------|
| 从[工厂](entries/factory.md) 滚到 **900px** → 点导航 | `scrollY = 900` ❌ |
| 从[地图对照速查](docs/map-guide.md) 滚到 **3000px** → 点导航 | `scrollY = 3000` ❌ |
| 从[总览页](entries/index.md) 滚到 1500px → 点导航 | `scrollY = 0` ✅ |
| 从[术语速查](docs/glossary.md) 滚到 2500px → 点导航 | `scrollY = 0` ✅ |

**注意 900 → 900、3000 → 3000：滚动位置是被原样保留的**，不是「归零失败」。再重复测三次同一场景，**同一站点、同样操作，结果还会不一样**——**这是间歇性缺陷**。这也解释了为什么第一次没测出来。

**根因**：站点启用了 Material 的 `navigation.instant`（XHR 换页、不整页刷新）。它的滚动复位是**靠不住的**——在网络时序稍有变化时就会跳过复位，把上一页的滚动位置带进新页面。

**修法：加一段兜底 JS（`content/javascripts/scroll-fix.js`）**

```js
document$.subscribe(function () {
  if (!window.location.hash) {
    window.scrollTo({ top: 0, left: 0, behavior: "instant" });
  }
});
```

- `document$` 是 Material 提供的 observable，**首次加载与每次 instant 切换后都会触发**；
- **带锚点的跳转不处理**——那是读者主动要求跳到某处，强制复位会打断它（本页内的「回到顶部」也是一样）。

**验证（三项都跑过）**：

| 检查 | 结果 |
|------|------|
| **产物里有没有这个文件** | ✅ `site/javascripts/scroll-fix.js`——**这一步必做**：`extra_javascript` 与 `extra_css` 一样，路径相对 `docs_dir`，放错位置会**静默失效**（本项目 `extra_css` 当年就栽过） |
| 页面是否真的引用它 | ✅ `src="../../javascripts/scroll-fix.js"` |
| 普通导航是否回顶 | ✅ `scrollY = 0` |
| **锚点跳转是否被破坏** | ✅ 访问 `/entries/factory/#boss` 仍正确滚到 2433px——说明 `location.hash` 判断生效 |

**P1 · 引言块的品牌蓝竖线从未生效**

[extra.css](https://github.com/GTX950L/tarkov-encyclopedia) 里写的 `.md-typeset blockquote { border-left: 4px solid var(--tk-brand) }` **一直被主题覆盖**：Material 有一条 `[dir="ltr"] .md-typeset blockquote`，比它多一个属性选择器，优先级更高。于是引言块的左侧竖线实际是主题灰 `rgba(0,0,0,.32)`，而背景色（`--tk-quote-bg`）正常生效——**一半生效一半不生效，所以肉眼很难发现**。

修法：选择器补上 `[dir="ltr"]`，并**同时写 `border-inline-start` 与 `border-left`**（防止主题换用逻辑属性后再次失效）。实测已变为 `4px solid rgb(63,81,181)`。

**P1 · 首页学习路径图改为零依赖纯 CSS**

首页原来用 `mermaid` 画九篇的学习路径。实测发现两个问题：

1. **它依赖境外 CDN**：站点 bundle 的 mermaid 是运行时从 `unpkg.com` 懒加载的 **3.57 MB** 单文件。弱网或离线时加载不出来，**首页第一屏会直接吐出一大段 mermaid 源码**（`flowchart LR A[第一篇<br/>入门机制...]`）——这与本站“弱网环境可流畅阅读”的定位直接冲突；
2. **即便加载成功也读不清**：九个节点横排时会被压成一排小方块，箭头上的关系文字完全看不见。

已改为**纯 CSS 的路径条**（九块品牌浅色卡片 + 箭头，可点击跳转），零额外请求、首屏秒出、可打印，并把原来的关系文字单独整理成一句递进说明。窄屏下自动折行。

**本篇最花力气的两个判据**

- **投掷物：“冲还是躲”其实不是一个问题，引信才是**。F-1 / RGD-5 为 **3.5 秒**、M67 为 **5 秒**、VOG-17 为 **2.5 秒**、VOG-25 为 **2 秒**、RGO / RGN **撞击即爆**——**2 秒和 5 秒是两个世界**：前者跑不出半径（正解是压低身体 + 贴硬掩体），后者才有选择权。并且**捂雷（cooking）没有实装**，所以**无法靠引信长度反推型号**，只能靠“落地之后多久才爆”来判断余量。另一条反直觉的结论：**雷落在隔断另一侧时，不动常常优于移动**（破片会被硬掩体阻挡）；
- **战斗中受伤：判据不是“哪个更疼”，是“哪个在我做别的事时还在杀我”**。据此把伤分成两类——**会继续变坏的**（出血 / 脱水 / 中毒，必须立刻处理）与**已经变坏但稳定的**（骨折 / 疼痛 / 黑肢，可以延后）。这一条直接解释了**为什么大出血必须排在骨折前面**：你在接骨的那几秒里，出血还在扣血。

**顺带纠正一条流传很广的说法**

- **“出血会在身后留下血迹、敌人与 AI 会顺着血迹找到你”——这个机制并不存在**，没有任何官方说明支持它。真正会出卖你的是**声音**（治疗动作、受伤声、脚步）与**现场痕迹**（尸体、开过的门与容器）。已写进[战中伤情处置](entries/combat-medical.md) 第 4 节。

**扩写（2 篇）**

- [食物与水分](entries/food-and-water.md) 新增第 6 节**「进图配置：带多少、带哪种、什么时机用」**——把前五节的原理落成出发前的清单：三问定配置（图多长 / 打几场 / 安全箱几格）、按图型的粗配置表、三条时机纪律；

**几处关键事实（本轮取材于官方 wiki 与官方补丁说明）**

- **武器故障的 93% 硬阈值**：**耐久高于 93% 时机械故障不会发生**——故障因此不是运气问题，而是**耐久管理问题**；四种机械故障的**主因各不相同**（退壳失败看耐久、**供弹失败看弹匣**、**枪栓阻塞只看过热与耐久，且严重阻塞只出现在耐久 ≤5%**）；
- **过热是独立于耐久的第二条路径**：四种过热状态逐级加重，其中**中度会降低“最大耐久”**（打掉的是余寿），**极限必然阻塞**；而**轻微过热就已经让枪管在热成像里可见**；
- **排除流程与两个加成**：**L 检查 → Shift+T 操作枪机**；“故障排除”技能到**精英可跳过检查**；主武器故障时若带**已上膛的副武器**，可获 **5 秒切换加速**——**这是“带副武器”最硬的理由**；
- **维修要付两次代价**：武器维修套件**需要藏身处工作台、且不能带进战局**；而 0.13 的「维修套件与强化」规则是——**修一次扣一截最大耐久**（扣多少看**武器保养**技能）、**强化再次维修会被移除**；
- **顺手校准一对全站最易混的概念**：**武器保养（Maintenance，维修相关）≠ [武器掌握](entries/weapon-mastery.md)（Mastering，命中给经验、改换弹动作）**；
- **食物与水分的选型知识**：**水比食物难找、耗尽更致命**（耗尽后持续掉血，且**会拖慢耐力恢复**）；**干货会把你喝干**（炼乳一类“高能量 + 高负水分”是典型陷阱），**罐头与配给口粮才是口粮主力**；
- **一条口径更正**：**成瘾系统至今未实装**——官方 wiki 把“药物成瘾 / 幻觉”列在**未实装功能**清单里；

### 新增条目 · [Scav 指挥与随从系统](entries/scav-command.md)（69 → 70 篇）：把“一句话的声望待遇”补成一套可操作的子系统

**起因**：读者读完[阵营关系与交战规则](entries/engagement-rules.md)后指出——“里面说 Scav 高声望可以指挥其他 AI Scav，这一块儿详细写一下”。核对后发现全站对此只有**两行**：`scav-relations.md` 表格里的“AI Scav 会听从指令甚至协同作战”、`karma.md` 表格里的“AI Scav 听令概率”。而真实机制是**一整套指令系统**——**单开一篇**。

**关键取材：官方 0.13.5 补丁说明的「对人机的命令」段落**（IGN / consolepcgaming / 中文 wiki 三处互证）。它把六个命令逐条写了出来，并明确三件事：**指令由玩家主动发出**、**每条都有冷却**、**能否被服从取决于 bot 与你 Fence 声望的关系**。

| 指令 | 范围 | 作用 |
|------|------|------|
| **帮助** | 区域级 | 附近 bot 前往你身边并与敌人交战——**唯一的“叫援兵”** |
| **跟随** | 单体级 | 跟着你移动（0.13.5 起手势与语音短语“跟我来”都可以下） |
| **分散** | 区域级 | 找掩体并散布，防被一锅端 |
| **掩护** | 单体级 | 你旁边那个 bot 占据最近掩体 |
| **静默** | 区域级 | 停止交谈、开始倾听——**唯一不改变任何人位置的指令** |
| **停止** | 单体级 | 短暂停下看你，然后继续——**用来换随从** |

**本篇另外补上四条此前完全没有的内容：**

- **最容易漏的一条**：**6.0 以上**的玩家 Scav **被敌对势力或叛徒攻击时，附近 AI Scav 会主动离开守区、跨距离赶来支援**（普通 AI 基本不离开自己的生成区域）。这条改写了高声望 Scav 的定位——**“不是一个人，是带着警报器的一个人”**；
- **随从数量：把冲突如实写出来**。社区有“只能带 1 个”与“可带 1–4 个”两种口径，**官方未公布**；给出的可执行结论是“**先按 1 个做计划**，用「停止」换人”；
- **纠正一条流传说法**：有攻略称 6.0 以上可以**指挥 Boss 护卫**，**官方从未这样表述**——官方在该档只写“**大多数 Boss 对你中立、不主动攻击**”。把“不被攻击”读成“能指挥”是两回事；
- **失效条件与代价**：随从是**第一批反水的**（叛徒判定当局限定、全场生效）；随从开火会替你广播位置；**AI 会搜尸并拿走装备，且这些物品不走保险**（官方更新日志）。

**顺带给出三套战术组合**：哨兵开路（“跟随”优先给护甲更好的那个）、静默潜行（首个指令性价比最高）、**伏击反制（分散 + 帮助 = Scav 唯一的“以多打少”窗口）**。

### 新增条目 · [遇敌处置与接战决策](entries/contact-drill.md)（68 → 69 篇）：把“遇到人怎么办”补上

**起因**：上一轮补完[阵营关系与交战规则](entries/engagement-rules.md)之后，读者紧接着指出了它的下一步缺口——“**拾荒者碰到人是先躲起来还是直接开枪**”。这一问在站内**没有正面答案**：既有内容回答的全是**机制问题**（Karma 怎么算、AI 怎么感知），而这一问是**决策问题**。判据很清晰：全站凑不出“遇到人之后的前 3 秒该怎么做”的一段完整说明。

**本篇给出的是一条可执行的决策流程，而不是又一份机制说明：**

- **前 3 秒的五问清单，且顺序不可换**：身份 → 他有没有发现我 → 距离 → 退路 → 收益。“先算收益再认人”正是塔科夫里最贵的错误的生产方式（为了杂货打成叛徒、为了一个人头招来一队人）；
- **两张身份线分开写**：同一个局面，PMC 与 Scav 的答案**经常相反**，原因见第 9 节的不对称；
- **距离决策带**：贴身（**先动多半赢**）/ 中段（标准接战距离，**别在同一个掩体露第二次头**）/ 远段（**先看你打不打得穿**）/ 超出有效区间（**不该开枪**，因为枪声是全图级的）——并指出“隔着很远就被打中”这件事**本身就是身份判据**（普通 AI Scav 不会在极远距离开火）；
- **先手的两面**：先手命中会让 AI **掉精度**，这是塔科夫最便宜的优势；但**枪声是全图级的信息**，且 AI 在约 50 米内互相通报、预编队不受距离限制——所以**先手是用来决定打不打，不是用来打的**；
- **三种必须脱离 / 两种必须抢先动手**的情形，其中后者包含对方正在做**翻尸体、开容器、打药**这三件脆弱的事；
- **“躲”的三种形态与判定**：**静止不动 = 最危险**（AI 不会“你躲起来就忘”，它会记住最后确认位置并搜索、绕行、包夹）、就地隐蔽 = **只对“还没确认你”的对手有效**、**断联脱离 = 唯一真正有效的一种**；
- **断联脱离的五个技术细节**（本篇最值钱的一节）：走**软地表**（金属 / 玻璃 / 木板 > 混凝土 > 泥土 / 草）、**用慢走消除地形噪音**、**别顺着来路回退**（那正是对方第一个要搜的方向）、**冲刺只留给“已确定脱离”的那一段**、有条件就**反向制造噪音**调虎离山；
- **开枪之后的三个窗口**（3 秒 / 10 秒 / 30 秒），以及一条固定纪律：**交火结束即默认有人在来**；
- **第 9 节“一条不对称”**：**PMC 的命带着资产，Scav 的命是免费的**——这一个事实改写了同一局面下所有人的答案。

**起因**：阅读反馈里最反复出现的一类问题，是**身份如何决定交战关系**——“作为 PMC 进图是不是可以射击任何人”“作为 Scav 面对同行 / PMC / Boss 各会怎样”“PvE 里是不是同一套规则”。这三问在站内是**分散**的：[敌我识别与身份判断](entries/iff.md) 讲**怎么认人**，[Scav 互动与叛徒判定](entries/scav-relations.md) 只覆盖 **Scav ↔ Scav**，[PMC 与 Scav](entries/pmc-scav.md) 讲**两种角色的收益结构**——**没有任何一篇回答“开火之后会发生什么”**。全站检索「交战规则 / 自由开火 / 开火规则」**零命中**，属真空缺。

**本轮的关键发现（也是本篇最重的两块内容）：**

- **官方把业力拆成了两套独立系统**。官方支持站 `knowledge/519`《Karma in Escape from Tarkov》写明：**PMC 有自己的一套业力，Scav 有另一套独立的声望 / 业力**。前者是**隐藏参数**，管“你这一局体面不体面”——**击杀队友**与**长时间停在同一个点不动**会降；后者就是 Fence 声望。两条官方给出的自查手段一并收进条目：**战局结算界面的「总体声望变化」一行**，以及**涨与跌各自不同的音效提示**。
- **PMC 业力的执法者是 Boss「Partisan」**：低 PMC 业力会提高他在战局中出现的概率并让他主动猎杀你；**即便你以 Scav 角色进图，只要 PMC 业力低，照样是他的目标**；他与 Fence 声望**完全无关**。

## 2026-09（v1.4.0）

### 新增：敌我识别与身份判断（47 → 48 篇）

- **第五篇 · 进阶战斗机制（+1 篇）**：[敌我识别与身份判断](entries/iff.md)——补上此前缺失的一条主线：塔科夫**没有队友名字、没有小地图、没有敌人轮廓**，判敌完全交还给玩家。

### 条目要点

- **敌我关系由“身份 + 行为”决定**：USEC 与 BEAR 之间没有任何和平机制；Scav 的和平是行为换来的（先开枪即被标记为叛徒）。
- **三级判据**：轮廓（Scav 的底层衣裤与袖子不随装备变化）→ 行为（AI 巡逻固定、不蹲下搜刮、不查弹匣）→ 声音（AI 常在开火前喊话；0.16.5.0 起近距离开火前必定先喊）。
- **队伍识别**：臂章（Armband）是唯一的官方手段——占专用槽位、**不能被拾取、死亡不丢失**，因此可以跨局固定颜色。
- **伪装与外观**：战术服装按上衣与裤子分件、BEAR 与 USEC 各有部件池，The Unheard 版可混穿，服装不再能证明阵营。
- **特殊身份**：Boss 护卫、Raider、Rogue、邪教徒、叛徒 Scav、Goons 的外观与行为线索，以及击杀各自带来的声望后果（灯塔 Rogues 是 AI 却穿得像 PMC，是本篇最重要的误判陷阱）。
- **事后确认**：狗牌显示姓名、等级、阵营与击杀者；击杀队友的狗牌失去“战局内发现”状态且价值 ₽1。
- **竞技场对照**：竞技场自 0.2.8.0 起在 TeamFight、BlastGang、CheckPoint 中把队友臂章强制为蓝色、敌人强制为红色——本体刻意不给，是设计取舍而非遗漏。
