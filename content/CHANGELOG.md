# 更新日志 (CHANGELOG)

本文件记录面向用户的条目内容变更。历史条目一经发布，只做修订不做改写。

> 📚 **分页口径**：本页只保留**当月**条目；跨月时把上个月整段移入仓库根的 `CHANGELOG-archive.md`（**内容原样搬，不改写一个字**）。
> 归档自 2026-10-22 起**移出站点构建** —— 更新日志是发布记录，不是资料页；读者要翻更早的版本看 GitHub Releases 即可，站内不再为 2,690 行历史付一次页面下载。

> **发版节奏（2026-10-26 起）**：**一个版本 = 读者能看见的一批变化**，一天最多一个。
> 门禁、体积、生成器内部实现与纯排版修正**不单独抬版本**，并入下一批；「一个版本一个 Release」的硬对应不变，Latest 仍须等于本页顶部版本。
> 判据与理由见[贡献指南](CONTRIBUTING.md) 的「版本粒度」一节（含 `v1.47.0` 起 151 个版本 / 122 个 Release 的实测）。

## 2026-11（v1.154.4）— 十章剧情各写成一页：起因、经过、结果

**触发**：读者问「这十个主线都有讲起因经过结果吗」。查下来**只有 3 章有**——门票写了结局、陨落星辰写了流程、塔科夫之旅只写了作用；其余 7 章在总览页各占**一行表格**（名字 + 目标数 + 「穿插」）。读者看完仍然不知道「无名者」讲的是谁、「Boreas」为什么重要。

### 一、十章各一页，统一按三段式写

新增 `content/story/` 下十页（导航在**第十篇 · 任务图鉴 → 剧情线逐章讲解**），每页结构固定：**起因**（谁托你办、为什么）→ **经过**（关键节点与分支）→ **结果**（改变了什么），末尾带「走这一章的几个判据」与「常见误解」。

| 章 | 这一章现在讲清了什么 |
|----|----------------------|
| 塔科夫之旅 | 指挥部留的是退路，路要自己走；结尾为什么落在实验室 |
| 陨落星辰 | 坠机调查的四幕；为什么等待是三段而不是一段 |

### 二、先说清素材边界：台词拿不到，不等于讲不了

## 2026-11（v1.154.3）— 三个剧情章节改回中文 Wiki 的叫法：塔科夫之旅、陨落星辰、门票

**触发**：有读者按中文 Wiki 的章名「门票」在站内找章节结局，搜出来的是道具页——因为本站这三章一直用一套自己定的名字。

### 一、正名换成中文 Wiki 那一套

| 英文名 | 旧（本站自定，1.154.2 及以前） | 新（中文 Wiki 正名） |
|--------|--------------------------------|----------------------|
| Tour | 游览 | **塔科夫之旅** |
| Falling Skies | 陨落之天 | **陨落星辰** |
| The Ticket | 车票 | **门票** |

其余七章（无名者 / 神秘蓝焰 / 他们已经来了 / 意外证人 / 探秘“迷宫” / Batya / Boreas）两套说法本来就一致，不动。

换的理由不是「哪个译名更雅」，是**口径**：本栏目的数据来源写的是「中文 Wiki 实测」，名字却另起一套——同一章在站内与数据源之间就有两个叫法。加上**检索习惯**：社区说的是「门票」，站内主用「车票」，按前者搜不到章节。

### 二、旧名没有删掉

[剧情章节与主线任务](entries/story-chapters.md) 的 §2.1 与「常见错误」各留一处说明：社区攻略与视频里的「游览 / 陨落之天 / 车票」就是这三章。**认英文名最稳**，这是本站一贯的口径。

### 三、已存的进度不受影响

章节进度是按 id 记的（`tour` / `the-ticket`），不是按中文名。改名不触碰任何已记录的三态标记。

### 四、改了哪些文件

真源 `scripts/data/storylines.json` 的三章 `zh` 字段 → 重跑 `gen_progress_manifest.py` / `gen_bundle.py`（两个产物里旧名残留 **0**）→ 正文同步 [剧情章节与主线任务](entries/story-chapters.md)、[终点站](entries/terminal.md)（2 处）、[灯塔](entries/lighthouse.md)（1 处）、[任务图鉴](quests/index.md)（1 处）、[我的进度](quests/progress.md)（1 处）。**CHANGELOG 历史条目一字未改。**

回归读数：`build_all` 的 ①–⑤b **全绿**；`zensical build` 无 issue。⑤c 因 `gen_achievements.py` 抓取成就数据时 SSL 握手超时没跑完（**环境问题，不是本次改动**），受影响的两支生成器已单独跑两遍、产物 MD5 不变。

### 五、顺手做完的归档，以及一个要记账的决定

已进 11 月，按本页的分页口径把 10 月整段（**154 条**）原样搬进仓库根的 `CHANGELOG-archive.md`（**逐字未改**，只更新了归档页的「收录范围」一行）。本页现在只剩当月条目。

搬之前核对了一件必须留档的事：**10 月有 33 个版本从没打过 tag、也没建过 Release**（`v1.112.0`–`v1.124.0`、`v1.128.0`、`v1.133.0`、`v1.134.0`–`v1.134.6`、`v1.135.0`–`v1.135.1`、`v1.136.0`、`v1.137.0`、`v1.138.0`–`v1.138.2`、`v1.147.9`–`v1.148.1`）。`release.py` 与 `backfill_releases.py` **只读本页、不读归档页**，所以这段历史一旦搬走就补不回来了。

**决定：这 33 个不再补发。** 写在这里是为了让后来查版本序列的人知道这是**一次明确的取舍**，不是又漏了一批——否则下次核查会把它当成新缺口，再查一遍。

### 六、顺带：物品图鉴对齐最新抓取（4,983 → 4,998 件）

合并前的 CI 在「Check item link wiring」这一步红了。查下来**与本章节无关**：那一步每次都会重抓 `items` 端点再重生成物品索引，而仓库里的图鉴快照是 **10-17** 的——接口这两周新增了 **15 件**（弹药类 444 → 446、全站 4,983 → 4,998）。不管本章合不合，这道门禁都会红。

所以一并把图鉴重新抓取对齐到 **4,998 件**，并同步了 **5 个文件、11 处**口径数字：[数据口径与引用说明](docs/citation.md)（3 处）、`llms.txt`（3 处）、[条目总览](entries/index.md)（2 处）、[站点首页](README.md)（2 处）、仓库根 `README.md`（1 处）。这些页面的 `catalog/*.md` 也随之重生（**30 个文件**，主体是件数与分册归属的连带变化）。

⚠️ 记一笔教训：这是一个**数字十一处落点**的典型——只改图鉴页，`check_entries.py` 会逐个点出来，实测**红了两轮**才齐。今后改图鉴件数，直接按上面五个文件一起改。

同一批还有一处：**成就页停在 128 个，接口已是 131 个**（普通 26 / 稀有 24 / 传说 67 / 活动 14，其中隐藏 25）。这是 ⑤c 那一步查出来的，一并重生成，首页速览的成就数随之从 128 改为 131。两处都是「快照放久了」的同一类问题，不是本章改动带出来的。
