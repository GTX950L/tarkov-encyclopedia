## 2026-11（v1.155.3）— 清一遍「AI 腔」：金句收口、元话语预告、同构排比

**触发**：有读者反馈（我自己读也膈应）——文案不像人写的，像模板套出来的。做了一次全站文本体检，问题不在词汇，在**句子的收口方式**：每节末尾都要来一句对偶格言，每个小节开头都要预告「这值得单独说」，九个商人的画像用同一个修辞骨架写九遍。这些都删了或改了，事实、引文、数据一个字没动。

### 一、体检：先量出来，再动笔

| 指标 | 结果 | 判读 |
|---|---|---|
| 词级套话（不仅…而且 / 值得注意的是 / 读者导向） | 全站 15 处 | 很少，不是问题所在 |
| 「不是X，是Y」反转句 | 338 处 · 0.4/千字 | 多数是**纠偏**（「PMC 业力不是惩罚，是排期」），保留；只改纯修辞的 |
| 加粗 21.3 对 / 破折号 3.7 处（每千字） | 稳定 | 这是 template.md 定的风格，**不动** |
| 跨篇复用的元话语 | 「这个细节很轻」「这一笔很轻」「这里有一个非常容易踩的坑」 | 最强的模板指纹，全部改直述 |

### 二、改了什么（四类）

- **金句收口**：把已经说完的事换个对偶句再说一遍的那种。例：`一个人在准备死的时候，才会这样写信` → `他已经在安排身后事了`；`「被带走」这三个字，比死亡更让人不安` → `下落不明比死亡更难查：死人留下尸体，被带走的什么也没留下`。涉及十章里的六篇，共删 4 句纯重复、改 3 句抒情。
- **元话语预告**：`值得单独记住：` `这是一把双刃剑，值得单独说清：` 这类「先告诉你这事值得说、再开始说」的句头，全站 9 处，改成直接说。
- **同构排比**：[商人群像](entries/trader-profiles.md) 里九位商人的画像原本是同一个骨架——「他卖的不是货，是『X』」——连写九遍。现在九句各说各的，判断没变（Prapor 管秩序、Therapist 只问能不能救人、BTR 司机手里唯一的路）。
- **抒情与对称**：`一件没能运走的武器，留在了原地；一份没来得及销毁的规格，落在了你手里`（[蓝焰](story/blue-fire.md)）——事实上一段已经讲完，这句只是换个说法再说一遍，删。

### 三、判定为「不改」的，以及为什么

| 看着像 AI 味 | 为什么保留 |
|---|---|
| `**一句话**：` 小节导语（[战区纪事](lore/industrial.md) 四篇各 12–14 处） | [产业志](lore/index.md)「怎么读」里明写「一句话看结论」，是排版规范；去掉标签反而伤扫读 |
| 各篇 `推测 A/B/C`、`📸本章速览`、`🧭判据` | 页面骨架，不是行文 |
| 327 处反转句 | 这个站的核心价值就是纠正常见误解，反转句是它的工具。只删装饰性的，不删干活的 |
| 加粗、破折号、emoji 小节标题 | `template.md` 定死的站点风格 |

## 2026-11（v1.154.9）— 任务页也能进人物页了，两头都通

**触发**：上一版把人物四页接进了十章正文、章节页、商人页与世界观页，但**任务图鉴这一头还是断的**。当时没做，是因为 `content/quests/*.md` 全部由 `gen_quests.py` 生成 —— 手改会被下一次重跑覆盖。这一版改生成器。

### 一、11 个商人页各加两行

商人页的「本页概览」里，前几行说的是**他有多少任务、等级跨度多少**，读者真正想问的却是「这人到底是谁」。所以每个商人页现在多两行：

| 新加的行 | 回答什么 |
|---|---|
| **🎯 这个人是谁** | 本页只写他给什么任务；来历、在卖什么、和谁有过节 → [人物与组织](entries/characters.md)、[商人群像](entries/trader-profiles.md) |
| **📖 剧情里的角色** | 十章里他是哪几章的**主导商人**，逐章给出链接 |

页脚也补了「人物与组织」「剧情章节与主线任务」两个出口；[任务图鉴总览](quests/index.md) 与[单个任务详情](quests/quest.md) 的「相关页面」同补。

### 二、为什么只能挂「页」，不能挂「任务」

原本更想要的是「这个任务里出现了谁」这种**任务级**锚点。核对数据后放弃了，**并将这条口径写进了商人页**：

- 剧情十章的任务线**不在**本栏目 —— 本栏目的 503 条取自 `json.tarkov.dev/regular`，任务表里搜 `Bogatyr`、`臂章` 均为 0 命中；
- 所以给章节造任务锚点会**指向一个不存在的任务**，读者点进去只会看到「找不到」；
- 页面上因此明写一句「**这些章节不列在本栏目**（`regular` 档案里搜不到）」，把「漏抓」与「口径」分开 —— 否则读者搜 Batya 搜不到，第一反应一定是本站漏了。

### 三、反方向也补上了

只做一半等于没做，所以两头都接：

- **十章 → 商人页**：`主导商人`／`唯一出手的商人`／`关键人物` 三处里的人名，现在都能点到对应商人页（Jaeger → 他的 64 个任务、Lightkeeper → 他的 14 个）；
- **人物页 → 任务页**：[人物与组织](entries/characters.md) 的商人表新增「**他给什么任务**」一列，11 位各接自己那一页，并注明两页分工 —— 任务页只写**定义**（要求、奖励、门槛），人物页只写**来历**，不重复也不互相矛盾。

### 四、三处「不留空白」

| 情况 | 处理 |
|---|---|
| Peacekeeper / Fence / Ref 在十章里没有主导章节 | 明写「**没有他主导的章节**，他的任务全在常规线上」—— 空白格会让读者分不清「没戏份」和「本站没写」 |
| Elektronik 出现在「主导商人」行里 | 标注「**他不是商人**」，并链到人物志而非某张商人页 |
| 蓝焰 / 门票 / 无名者三章没有「主导商人」行 | 用该章已有的「唯一出手的商人」与「关键人物」补链接，不新造一个章节分工 |

### 五、新增门禁 8b：双向链接成对核对

`check_entries.py` 新增一条 —— 任务图鉴的**每个商人页**（`quests/` 下除 index / quest / progress / item-lookup / tree / event-quests 之外的全部，新增商人自动纳入）必须链到 `characters.md`，且 `characters.md` 必须链回每一页。**反向验证过两条**：删掉 prapor 页的人物链接 → 报「任务页未链接到人物页」；删掉人物页的 ref 链接 → 报「人物页未链接回任务页」。

这类断链**页面本身不会报任何错**，只会让读者走着走着没路了 —— 正是必须机器盯的那类。

### 六、连带刷新

图标 **2838 → 2868 处**（11 个商人页各加 🎯 与 📖 两个，其余为总览/详情页入口）；内部链接 **4563 → 4684 条**；任务数、条目数、篇数均未变。
