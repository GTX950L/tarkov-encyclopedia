# 我的进度

<a id="top"></a>

> 第九篇把 515 个任务逐条列全了，但**进度记在哪**一直是本站的空档 —— 游戏内不给整体视图，跳蚤市场也查不到，每局都要靠回忆「这个我交了没有」，而回忆会出错。
>
> 这一页只让你填**两件当下就知道的事**：**我的等级**、以及**任务列表里手上正拿着的那些任务**。其余由任务前置树推出来 —— 你不用回忆过去做过什么。

| 项目 | 说明 |
|------|------|
| **记什么** | ① 任务（进行中 / 已完成）② 剧情章节（10 章）③ 物品已囤件数（79 种）④ 藏身处模块等级与材料（26 个模块） |
| **怎么记** | 任务与剧情章节：本页或对应页（任务页 / 剧情页）的控件，或**从游戏日志同步**（见「进度管理」分页）；物品与藏身处：本页直接改数字 / 选等级 |
| **分模式** | PVP / PVE / 赛季 三套独立记录，页面顶部的进度模式条切换 |
| **存在哪** | 本机浏览器的 localStorage，**不联网、不上传、不需要登录** |
| **换设备** | 用「进度管理」分页的导出 / 导入（任务取并集、件数与等级取较大值、剧情章节取较强状态） |

> ⚠️ **清单是持久 PvP 口径**：PVE 与赛季模式的任务／藏身处有增删差异，本站没有逐条标注 —— 切到那两个模式时看到的仍是这份清单，只是记录记在另一个账本里。三个账本之间互不影响。

<div id="tk-statusbar" data-statusbar>进度状态条需要 JavaScript 才能显示；本页其余说明不需要脚本。</div>

=== "总览"

    **一眼看清五条线的进度**：任务（按商人拆开）、长线目标、剧情章节、藏身处、物品收集 —— 全部读自你本机的记录，不需要登录。

    每一块都标着**这条数是怎么算出来的**：任务的「已完成」分「手动」与「推断」两个数（推断 = 由进行中任务沿前置树反推），两者不混在一起算。

    <div id="tk-board-overview">进度总览需要 JavaScript 才能显示；本页其余说明不需要脚本。</div>

=== "任务进度"

    只填你**现在就知道**的东西：**我的等级**、**门槛**（商人忠诚度 / 阵营 / 转生）、以及**任务列表里手上正拿着的那些**。它们的**前置会被自动算作已完成** —— 你不用回忆过去做过什么。

    工具栏从左到右：**等级** ｜ **阵营** ｜ **「门槛」**按钮（收起状态，点开里面是 11 个商人的忠诚度、**Fence 声望（可填负数）**与转生次数）｜ **搜索**（覆盖全部 515 个任务）。下面一行是**地图筛选**与三个预设：**Kappa 线** / **Lightkeeper 线** / **出发前准备**。

    每个任务行左侧是**三态分段按钮**（未标记 / 进行中 / 已完成）—— **点一下就切**，不用点开下拉再选。行首的**色条**与状态一一对应：琥珀 = 进行中、绿 = 已完成，扫一眼就知道哪些在做。

    每个任务行都能展开看**目标清单**（全站 1441 个目标）—— 勾完目标，任务会自动记为已完成；只勾一部分，任务记为进行中。

    <div id="tk-progress-board">进度看板需要 JavaScript 才能显示；本页其余说明不需要脚本。</div>

=== "依赖树"

    **这棵树不是用来看全貌的，是用来回答两个问题的**：手里这个任务**卡在哪个前置**，以及做完它**能放开哪些**。
    两向都只算**状态为「完成」的前置边** —— 与上方「可接」判定、[任务图鉴的优先级速查](index.md)同口径。

    - **上游链**：做它之前必须先完成什么，按「第 N 层前置」由远及近排（未完成的标出来）；
    - **下游收益**：做完它之后逐层放开哪些，按「近的在前、同级里自己放开多的在前」排。

    入口有三处：**从我在做的任务出发**（列你标成「进行中」的那些）、**两条长线的终点**
    （收藏家 / 守望者箴言 —— 倒着看最有用），以及**搜任务名**。

    每个节点右侧有一枚**状态芯片，点一下就切换**（未标记 → 进行中 → 已完成）——
    不用跳回「任务进度」分页。节点名可点，跳到该商人的明细。

    <div id="tk-board-tree">依赖树需要 JavaScript 才能显示；本页其余说明不需要脚本。</div>

    > **搜索只按中文名。** 图数据里没有英文名 —— 要按英文名找任务，用[任务图鉴总览](index.md)的筛选器。
    > 这一条写在界面上，免得搜不到被当成「没有这个任务」。

=== "物品收集"

    口径与[任务图鉴总览](index.md)的「物品需求反查」表**完全一致**：把 515 个任务里真正要上交或放置的物品按物品聚合，只列**被 3 个及以上任务需要**的那些（共 79 种）。

    **按件记，不按「有 / 没有」记**：79 种里有 75 种的合计需求在 10 件以上（卢布 440 万、BEAR 狗牌 575 枚），两态表达不了「还差多少」。

    <div id="tk-board-items">进度看板需要 JavaScript 才能显示。</div>

    > **两个容易读错的数**：
    >
    > - 「**合计数量**」是这些任务要求的**总件数**（跨任务求和），不是单次需求 —— 别照着一个数字一次囤齐；
    > - 「**达标**」只表示件数够了，**不代表任务能过**。约一半的需求带 **必须战局内找到** 的限制，跳蚤市场买的不算数。

=== "藏身处"

    **26 个模块、68 个等级、317 条材料**，逐级列在[藏身处模块](../entries/hideout-modules.md)页的 [§7 逐级材料清单](../entries/hideout-modules.md#materials)里。这一栏把它变成可操作的：选定模块当前等级后，直接显示**下一级需要哪些材料、要几件**，以及该级的前置设施、技能要求与施工时长；顶部按 **现在可升 / 前置未通 / 材料未齐 / 已建满** 四档筛。

    <div id="tk-board-hideout">进度看板需要 JavaScript 才能显示。</div>

    > **「现在可升」＝ 前置设施已通 ＋ 材料已齐。** 前置逐条判定（满足打勾、不足写「现有 N 级」），
    > 「前置未通」的卡片直接写明还缺哪个模块的几级 —— 前置关系取自数据端点的 `levels[].stations[]`（**126 条边**）。
    >
    > **技能要求只提示不判定**：技能等级是游戏内状态，本站不记录，所以那一条标成「未入册」而不是判它合不合格。
    > **两句话要分开读** —— 前置有数据、技能没有，不是一回事。

=== "剧情章节"

    **10 个剧情章节的三态记录**：Tour（游览）→ Falling Skies（陨落之天）→ The Ticket（车票）是叙事主轴，其余七章穿插其间 —— 章节清单、四个结局与前置关系见[剧情章节与主线任务](../entries/story-chapters.md)。

    **这条轨是纯手动记录、不做任何推断** —— 与任务轨的「前置反推」刻意不同：官方任务数据里没有「章节」字段、也没有章节→任务的映射，**算不出来就不算**，你标什么就是什么。

    <div id="tk-board-story">剧情看板需要 JavaScript 才能显示。</div>

    > 与其它轨一样分 **PVP / PVE / 赛季** 三套独立记录（页面顶部的进度模式条切换）；剧情页那张「已收录的十章」表里也能直接标（同一份数据）。

=== "进度管理"

    任务、剧情章节、物品收集、藏身处 —— 全部记录打成一个 JSON 文件导出；换设备时导入 —— **任务取并集、件数与等级取较大值、剧情章节取较强状态**，都不会覆盖已有的进度。

    另可**从游戏日志同步**：选一次本机的塔科夫 `Logs` 文件夹（或其中的日志文件），把已经发生的「接取 / 完成」一次性补进账本 —— 解析在**本页内存**里完成，**不上传、不保存**。藏身处、等级、目标级勾选与物品数量日志里没有，仍需手勾。

    记录可以**分轨清空**（任务 / 目标 / 物品 / 藏身处 / 剧情，只清当前模式）；「**清空全部进度**」把 **PVP / PVE / 赛季 三个模式**一次清掉（连等级与门槛）—— 不可撤销、没有回收站，动手前请先「导出进度」留一份备份。

    <div id="tk-board-ops">进度管理需要 JavaScript 才能显示。</div>

=== "说明"

    ### 怎么用（推荐顺序）

    0. **先看「总览」**（本页第一个分页，默认打开）：四条线各自的完成度、按商人拆开的分部进度、
       以及一条「下一步」建议 —— 想确认「我打到哪了、接下来干什么」看它。
    1. **再选定模式**（页面顶部的进度模式条），然后到「任务进度」分页开始记录。
       —— **已经玩过一段时间的话**：先到「进度管理」分页用**「从游戏日志同步」**一次性补齐历史（读本机日志、不上传），剩下的再手勾。
    2. **填「我的等级」**，展开「门槛」把常用的几个商人忠诚度填上；**做 Fence 任务的话，填一下 Fence 声望**（那个框**可以填负数**）。
       —— 515 个任务里有 **296 个没有前置**，不按等级和门槛筛，「可接」就等于全部任务。
    3. **把手上正拿着的任务标成「进行中」**。在「可接」里找，或用搜索框搜任务名。
       —— 它们的**前置会被自动算作已完成**，你不用回忆过去做过什么。
    4. **任务做完后改成「已完成」**，下游的前置状态会跟着更新。
       想更细就点任务行的「**目标**」展开，逐条勾 —— 全勾完任务会自动变已完成。
    5. **出门前**打开「出发前准备」预设：它把进行中任务里**要带 / 要找**的东西聚成一张表，
       并标出哪些**必须自己带出来**（跳蚤市场买的不算数）。
    6. 剧情章节、物品与藏身处按需要记（剧情章节也可在[剧情页](../entries/story-chapters.md)就地标记）；换设备用「进度管理」的导出，或**直接把分享链接发给别人**。

    ### 三种状态与两个推断

    | 状态 | 谁决定 | 含义 |
    |------|--------|------|
    | **进行中** | 你填（或由目标推导） | 任务列表里现在拿着的任务 |
    | **已完成** | 你填 ＋ 系统推断 | 手动标过的 ＋ **由「进行中」沿前置树反推出来的** |
    | **可接** | 系统推断 | 前置全部完成、**等级够、门槛也满足**、且还没做 |

    **推断规则**：能被接到的任务，其前置必然已经满足 —— 所以「进行中任务的所有前置」判定为已完成，显式标过的「已完成」同样向上传播。只沿「必须已完成」这一类前置传播。

    ### 门槛：能算的算，算不出来的标出来

    「可接」会同时判定四类门槛（都来自官方数据端点）：

    | 门槛 | 涉及任务 | 本站怎么处理 |
    |------|----------|--------------|
    | **商人忠诚度** | 110 条 | 用你在「门槛」里填的 LL 判定 |
    | **Fence 声望** | 10 条 | 用「门槛」里的 **Fence 声望**判定 |
    | **阵营（BEAR / USEC）** | 12 条 | 用工具栏的阵营判定 |
    | **转生次数** | 3 条 | 用「门槛」里的转生次数判定 |
    | **商人内部计数器** | **164 条** | **判定**：按「该商人已完成几个任务」算（见下） |
    | **Lightkeeper 声望** | 3 条 | **不判定**，只在行上提示（站内没采集这个刻度） |
    | **需与商人对话** | 12 条 | **不判定**，只在行上提示（没有对应状态可依据） |

    > 后两类本站没有对应的状态可依据 —— **宁可多提示一句，也不给一个看起来精确、实际靠猜的筛选结果。**

    **商人内部计数器（2026-10-11 起参与判定）**：端点给的是「**在该商人处推进到第几环**」
    （每个商人一个计数器、互不跨商人），这与「该商人已完成几个任务」同一把尺 ——
    **算得出来**，所以用来筛「可接」。被它挡住时，任务行会写明**还差几个**
    （如「需 Mechanic 环数 ≥ 3（已完成 1）」），搜任务名仍能搜到。

    它此前只当提示不判定，是「网页说能接几百个、游戏里远没有这么多」的主因 ——
    塔科夫一大半任务正是靠这个柜台顺序解锁的。

    ⚠️ **Fence 声望要单独填，而且可以填负数。** 它和上面 11 个商人的忠诚度**不是一把尺**——
    忠诚度只有 1–4 的正值，而 Fence 的门槛要求声望**为负**（亡羊补牢四条要求 ≤ −1 / ≤ −3）。
    所以「门槛」面板里它是一个独立的数字框，**允许负数**。

    | Fence 声望填了 | 判定方式 |
    |---------------|----------|
    | 填了具体数值 | **真判定**：≥ / ≤ / < 三种方向都按你填的值算（含负数） |
    | **留空** | 按「未知」处理 —— **只在任务行上提示条件，不计入「可接」，也不拦掉** |

    > 这条对应[数据口径与引用说明](../docs/citation.md) 第三节的 **B11**：站内**只采集 Fence 声望**这一个刻度，
    > 所以 Lightkeeper 那 3 条走提示。**这不是数据缺失的临时补丁，是「不采集就不假装能判」的处理。**

    ### 出发前准备

    从**进行中任务**的目标里聚合出「要带 / 要找」的东西，**先按地图分组** —— 出门前心里想的是「今晚去哪张图」，所以清单也按图组织；没有固定地图的归到「多图 / 未标注」。

    每张图内**缺口排在最前**并标红「缺 N」，已齐的沉到底部并淡化；再分成**必须战局内带出**（跳蚤市场买不到）与**可采购**两个区。数量与「物品收集」里的已囤件数对照 —— 这两条轨用的是同一份数据。

    > ⚠️ 按地图分组依赖任务数据里的地图字段，而**该字段只有约一半任务有**（数据源限制）。所以「多图 / 未标注」那一组里混着跨图任务和确实没标的，不是分组出错。

    ### 分享进度：一条链接，不用登录

    「进度管理」里的**复制分享链接**会把你的进度压进一条 URL（典型一二百字符）。对方打开后会被自动带到该分页，选择「合并进来」即可 ——
    **不需要账号、不需要服务器**，数据全程留在浏览器里。合并规则与导入一致：任务取并集、件数与等级取较大值，不会覆盖已有进度。

    > 链接里的数据带**版本指纹**；若对方的站点数据已更新，会先提示「可能有个别条目对不上」再让他决定。

    ### 这个功能刻意不做的事

    | 不做 | 为什么 |
    |------|--------|
    | **不在后台自动读游戏数据** | 网页不会自己碰你的磁盘 —— 没有监听进程、没有常驻。只有你**手动选一次日志文件夹**时，文件才会在**本页内存**里解析：不上传、不保存、关掉即弃（见「进度管理」的日志同步）。**截图识别**仍然不做：那需要上传图片 |
    | **不判定技能等级** | 技能等级是**游戏内状态**，本站没有数据可依据（**注意：设施前置不在此列** —— 前置取自数据端点的 `levels[].stations[]`，是判定的） |
    | **不猜「没标过的任务做没做」** | 推断只沿**有依据的边**（进行中任务的前置）走。没有依据的一律留在「可接」，宁可让你多看一眼，也不给一个看起来精确、实际靠猜的完成度（**日志同步不是推断**：它读的是游戏自己写的既成事实） |
    | **不推断剧情章节** | 官方任务数据里没有「章节」这层结构、也没有章节→任务的映射 —— 章节轨只记你亲手标的三态，**一个数都不外推**（宁可这条轨什么也不算，也不编一个百分比） |
    | **不做账号、不做云同步** | 本站是静态站，没有服务端 |

    ### ⓘ 数据与隐私

    本站不收集任何个人信息，也没有服务器可以收集。进度写在你自己浏览器的 localStorage 里，键名 `tarkov_progress_v1`，删掉它就等于清空全部进度。

    - **物品与藏身处的键是中文名**（这两份派生数据里没有稳定 id）。若将来官方译名变动，旧记录会失效 —— 任务与剧情章节两栏不受影响，它们用的是 id（任务用数据端点 id、章节用站内清单 id）；
    - **日志同步在本页内存里完成**：你选中的日志文件不会被复制或保存，解析结果只写进本页的 localStorage；页面关掉，中间数据不留痕；
    - **浏览器隐私模式 / 禁用 localStorage** 时记录在当前页面内仍可用，但**关掉就没了**（脚本会静默降级，不弹错）；
    - **导出文件是明文 JSON**，含全部记录（任务 / 剧情章节 / 物品 / 藏身处）与三个模式的进度，没有身份信息。它和你的游戏存档无关，只对本站这一页有意义。
